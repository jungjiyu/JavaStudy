root-context 객체 정리

jdbcTemplate :  직접 connection 생성 하지 않고도 쿼리문 실행할수있게해주는 객체. 
	: jdbcTemplate 객체를 대상으로 query( 쿼리문, RowMapper객체, 물음표에들어갈값들), queryForObject( 쿼리문, RowMapper객체, 물음표에들어갈값들), update(쿼리문, 물음표에들어갈값들) 메서드를 사용하여 쿼리문 을 실행시킨다
	: mybatis 를 쓰건 안쓰건 db 쓸꺼면 있어야된다

PlatformTransactionManager : 트랜젝션 구현할 수 있게 해주는 객체. 우리가 직접 스프링이 알아서 definition , status 객체를 생성해서 써야된다

TransactionTemplate: 쉽게 트랜잭션 구현할 수 있게 해주는 객체. 스프링이 알아서 definition , status 객체를 생성해준다
	: 만약에 이걸 쓸꺼면 PlatformTransactionManager 는 쓰면 안된다 (둘이 겹친다)


트랜잭션(Transaction) 이란 : 데이터베이스에서 CRUD 과정이 오류 없이 성공했을때만  그 결과를 반영(commit)하고, 오류 발생 시 그 결과를 반영하지 않는것(rollback)

트랜잭션 매니저 클래스 빈 설정
	: 스프링 같은 경우는 PlatformTransactionManager 를 통해 추상화 처릴를 한다
		: 그러니까 PlatformTransactionManager 가 인터페이스 타입이고, JDBC 상에서 트랜젝션 DataSourceTransactionManager 

	: 아래와 같은 꼴로 필드를 만들고 DI 시킨다
	@Autowired
	private PlatformTransactionManager tranManager;

	: 사용하기

		// 트랜젝션이 구동하는데 기본적으로 필요한 객체 << 트랜젝션 전파를 하는데 필요한 기본적인 객체
		// 트랜젝션이 구동하는데 기본적으로 필요한 객체 << 트랜젝션 전파를 하는데 필요한 기본적인 객체
		TransactionDefinition definition = new DefaultTransactionDefinition();
		
		// 트랜젝션매니져 객체로부터 얻어온다
		//TransactionStatus >> 트랜젝션 실행 및 상태를 제어할 수 있는 객체 . 이제 상태 제어를 스프링에게 맞기겠다
		TransactionStatus status = tranManager.getTransaction(definition);
		
		try {
		// 포인트 차감
		String query1 ="UPDATE MOVIE_MEMBER SET POINT =POINT-? WHERE USER_ID=?"; 
		// 티켓 장수 올려주기
		String query2 = "UPDATE MOVIE_TICKET SET TICKET_NUMBER = TICKET_NUMBER + ? WHERE USER_ID=?"; 

		jt.update(query1, ticketNumber*MOVIE_PRICE ,userId); // MOVIE_PRICE 는 인터페이스에서 상수로 선언해둠
		jt.update(query2, ticketNumber,userId);
		
		tranManager.commit(status); // 오류 없이 정상적으로 실행되면 commit 한다
		}catch(Exception e) {
			e.printStackTrace();
			tranManager.rollback(status); // 오류발생하면 rollback 처리한다

		}




TransactionTemplate
	
	: PlatformTransactionManager 를 사용하여 개발자가 트랜잭션의 시작 및 종료 시점을 명시적으로 결정할 수 있다. 하지만 PlatformTransactionManager 보다 더 간편한 방법으로는 TransactionTemplate 을 사용하는 방법이 있다.
	: 오류가 발생하면 알아서 rollback, 처리, 제대로 되면 알아서 commit 처리 해준다


	<!--  트랜잭션 매니져 클래스 빈 등록 설정-->
	<bean id="transactionManager" class="org.springframework.jdbc.datasource.DataSourceTransactionManager">
		<property name="dataSource" ref="dataSource"></property>
	</bean>
	
		<!--  트랜잭션 템플릿 빈 등록 설정-->
	<bean id="transactionTemplate" class="org.springframework.transaction.support.TransactionTemplate">
		<property name="transactionManager" ref="transactionManager"></property>
	</bean>

	: xml 에서 SQL 명령어 태그
		: SELECT문은 <select> 이고 반환값은 검색 결과 
		: INSERT문은 <insert>, UPDATE문은 <update>, DELETE문은 <delete>이고 결과값은 성공한 record 수 

	: SQL 명령어 태그안에 들어가는 속성
		: 검색결과(select) 가 아닌 경우 딱히 resultType 혹은 resultMap 속성을 사용하지 ㅇ낳아도 도니다
		(1) id : 구현할 메소드명(== 인터페이스에 선언된 메서드명)
		(2) resultType: SELECT문 실행 결과를 담을 객체를 지정한다. (패키지 이름을 포함한 클래스 이름 또는 객체 alias 지정)
		(3) resultMap : SELECT문 실행 결과를 담을 객체를 resultMap으로 지정한다. <resultMap>을 따로 선언해줘야 한다.
			: 결과가 리스트건 아니건간에 그런듯?
(resultType과 resultMap 중 하나를 택해서 설정한다.)
