	: Build vs Compile >> 
		Compile :  javac 라는 컴파일러가 소스코드(.java)를 바이트 코드(.class)로 변환하는 과정
 			: 주의) jvm 은 .class 파일을 실행시키는 얘임

		Build :  Maven, Gradle 등의 빌드툴이 소스코드를 JAR, WAR 등의  실행 가능한 독립적인 산출물로 만드는 과정
			: Compile ⊂ Build 로. Build 과정에서 Compile 이 일어난다
			: 빌드툴 >>전처리(preprocessing), 컴파일(Compile), 패키징(packaging), 테스팅(testing), 배포(distribution) 기능을 제공

	: 스프링 부트 프로젝트 구성
		▼ build.gradle : 빌드 설정(라이브러리, springboot버전,jdk버전)
		▼src
			▼main : 
				▼java : 자바파일이 저장됨
					▼기본패키지 : 프로젝트생성시만들어지는기본패키지 
						→ atrifact명Application.java : 프로젝트 생성시 기본 생성되는 클래스
							: @SpringBootApplication : 프로젝트 생성시 기본 생성되는 클래스에 붙는 어노테이션
								: Spring의 @Configuration과 동일한 역할을 수행. 즉, 사용자가 추가적으로 빈이나 설정 클래스들을 등록할 수 있도록 해준다.
								@SpringBootApplication = @SpringBootConfiguration + @EnableAutoConfiguration + @ComponentScan
									@SpringBootConfiguration : 사용자가 추가적으로 빈이나 설정 클래스들을 등록 가능하게 함
									@EnableAutoConfiguration : jar properties를 기반으로 자동으로 의존성 설정
									@ComponentScan : @Component가 적용된 클래스들을 스캔하여 자동으로 빈 등록

							: main 메서드가 정의되있음

						▼controller 패키지: controller 클레스 저장
							→ XXXXController.java : 컨트롤러 역할의 클레스



				▼resources : 외부 파일(html 등)이 저장됨
					▼static : 클라이언트가 직접 명시해 request 하는 파일들 저장 위치
					▼templates : 뷰 템플릿 저장위치
			▼test :

	: 웹 서비스의 동작 원리
		: 클라이언트-서버
			: 클라이언트 >> 서비스를 사용하는 프로그램. 컴퓨터 --> 브라우저 
			: 서버 >> 서비스를 제공하는 프로그램. 컴퓨터 --> 스프링 부트
				: 스프링 부트는 톰캣이라는 서버를 내장하고 있고, 이에 의해 서버로써 동작한다.

			: 클라이언트의 request 따른 서버의 response 로 동작
				: 당연히 서버가 실행중이어야 response 가 가능

		: RUN 하고 브라우저에서 request 하기
			: IDE(서버) 에서의 변경 사항( html 파일 내용 변경이건 .java 변경이건 )은 클라이언트 측에서 새로고침 한다고 반영되는게 아니다. ctrl+f9 하여 재빌드 하거나 서버 재시작을 해야 반영된다.
			: RUN 버튼은 main 메서드가 있어야 누를 수 있다
			: localhost:8080  >> 내 컴퓨터의 8080 포트에서 수행되는 서버에 접속요청
				: localhost == 127.0.0.1 >> 내 컴퓨터의 주소
				: 8080 == 포트번호

			: localhost:8080/파일명.html >>  서버에 파일을 직접 요청 . 
				: src/main/resources/static 에서 해당 파일을 찾아 response 함
