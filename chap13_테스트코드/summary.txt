
Arrays.asList( 데이터1, 데이터2 .. .) || Arrays.asList( 배열 )
	: arg 로 들어온 데이터들 혹은 배열을 "정적인" list로 만들어 반환
		: "정적" 이므로 반환값 자체론 add 나 remove 불가
		: ex )  
			List<People> peopleList = Arrays.asList( new People("김나방"),  new People("박나방"),  new People("저나방") ) ;
			List<Integer> numberList  = Arrays.asList( { 1,3,4,5,6,7 } )

	: 만약 반환된 list 를 동적으로 사용 원하면 "new ArrayList<>( 반환받은정적리스트명 )" 으로 일반 리스트로 새로 만들면 됨
		List<People> newPeopleList = new ArrayList<>( peopleList );

테스트 코드  : 프로그램이 의도 대로 잘 동작하는지 확인 하는 과정. 사람이 일일이 요청하지 않고도 검증 절차 자동화.
	: 테스트 코드는 main 과 같은 수준에 있는 test 디렉터리 내부에 저장됨
		▼test
			▼java
				▼com.example.lalala
					▼테스트 코드들




	: 작성 방법
		1. 서비스 클래스의 메서드를 오른쪽 버튼으로 클릭 - generate - test 
		2. JUnit5 으로 testing library 설정 후 테스트 코드 작성 원하는 메서드 클릭
			: 이케 하면 test/java/ 아래에 클릭한 메서드가 속한 클래스와 거의 유사한 구조로 테스트 코드 기본 구조가 생성됨
				: 클래스 명은 "기존클래스명Test.java"
				: @Test
					: 테스트 클래스 내부 메서드 수준에 붙어있음
					: 해당 "메서드" 가 테스트를 위한 코드라고 선언하는 것.

		3. 생성된 클래스를 직접 조작
			(1) 해당 테스트 클래스 위에 @SpringBootTest 작성
				:  @SpringBootTest  >> 해당 클래스를 스프링부트와 연동해 통합 테스트를 수행하겠다고 선언하는 것.
					: 스프링 부트가 관리하는 객체들을 DI 받을 수 있게 된다.

			(2) 테스트 클래스 내부에 필요한 환경 구성
				: "원본 클래스"를 @Autowired 받게 해놓음
					: 원본 서비스 클래스처럼 repository 를 @Autowired 시키는게 아니라 , 원본 클래스를 @Autowired 받게 하는거임 주의!! 


			(3) 테스트 메서드( @Test 붙은 메서드) 내용 작성
				0. 실패할 경우를 대비해 테스트 클래스에 @Transactional 붙이는거 추천
				1. 예상 데이터 작성하기 : 3. 의 assetEqauls 의 비교 대상으로 넣기 위함
				2. 실제 데이터 획득하기 : @Autowired 받은 원본 서비스 클래스 이용해 실제 데이터 획득
				3. 예상 데이터와 실제 데이터 비교해 검증
					: assertEquals( 예상데이터.toString( ) , 실제데이터.toString );
					: expected 와 actual 로 정리되어 비교 쉽게 로그 찍힌다.

		4. 테스트 코드 실행하기
			: 특정 테스트 케이스 하나만 실행 원하면 해당 메서드 옆의 play 버튼 누름 되고, 전체 테스트 케이스 실행하고 싶으면 테스트 클래스 옆 play 버튼을 누른다.
 
	: 테스트 코드 실행했을 때 잘 돌아가면 리팩터링 해서 코드 개선함 되고, 잘 안돌아가면 디버깅함 됨.
	: 테스트 케이스 test case >> 프로그램이 동작될 다양한 상황
