			: DTO 의 기본생성자와 getter/setter 가 필수인 이유 >> Reflection API 
				: Reflection API >> 자바에서는 JVM이 실행되면 작성된 자바 코드가 static 영역에 저장된다. Reflection API는 이 정보를 활용하여 구체적인 클래스 타입을 알지 못해도 클래스 이름을 통해 static 영역에서 그 클래스의 정보(메서드, 타입, 변수 등등)에 접근할 수 있게 해준다.
					: @RequestBody 나 JPA 에 Reflection API 가 사용되고, Reflection API 는 생성자와 getter 를 필요로 한다고 한다.

DDL DML , DCL
	: https://velog.io/@ksk5401/DDL-DML-DCL-%EC%9D%B4%EB%9E%80

	데이터 정의어 DDL Data Defintion Language >> 
		: 데이터(테이블)를 정의하는 언어. 
		: create , alter(테이블 수정), drop, trucncate (테이블초기화)

	데이터 조작어 DML Data Manipulation Language
		: 정의된 데이터(테이블)에 입력된 레코드를 CRUD 하는 언어
		: select, insert, update , delete

	데이터 제어어 DCL Data Control Language
		: 데이터(테이블)을 저장하거나 객체에 권한을 주는 등의 역할을 하는 언어
		: commit, rollback, grant ( db사용자에게 수행권한 부여) , revoke  ( db사용자의 수행권한 박탈)
 

데이터베이스 DB >> 데이터 관리 창고
	DBMS DataBase Management System >> DB 의 데이터에 접근할 수 있게 해주는 소프트웨어

관계형 데이터베이스 RDB Relational DataBase >>KEY, VALUE 값을 ROW(RECORD) 와 COLUM(TUPLE) 으로 이뤄진 table 형식으로 저장 
	: RDB ⊂ DB
	: (자바언어가 아닌) SQL querey 문으로 동작
	: 관계형 데이터베이스 시스템 RDBMS Relational Database Management System >> RDB 데이터 접근할 수 있게 해주는 소프트웨어
		: MySQL , Oracle , MariaDB, H2 등 있다


ORM Object Relational Mapping >> 객체(class)와 RDBMS의 테이블을 매핑시켜주는 프레임워크
	:  SQL Query가 아닌 직관적인 코드(메서드)로 데이터 조작 가능하게 한다.


JPA Java Persistence API >> Java 진영에서 ORM기술 표준으로 사용하는 "인터페이스" 
	: 그러니까 자바언어로 DB에 명령 내릴 수 있게 하는 얘다
	: persistence 영속성 >> 데이터의 영속성. 즉, 프로그램이 종료되더라도 사라지지 않는 데이터 성질.
		: volability 휘발성 과 대립되는 개념
	: Hibernate, OpenJPA 등이 인터페이스인 JPA 의 "구현" 클래스이다.
		: JPA 는 인터페이스이기 떄문에 JPA 기능 사용을 위해선 구현해야된다
	: 사용하는이유(장점)
		1. DBMS 종속성이 줄어든다 : DBMS 가 변경되더라도 소스 수정 필요가 없다
		2. 객체 중심 개발이 가능
			>> 가독성과 유지보수성이 높아진다.
			>> 객체 간 상속관계를 표현가능하다
			>> 객체 간 연관관계(클래스가 다른 클래스타입의 필드를 가짐)를 표현가능하다
	: 주의 ) JPA 는 수정 메소드를 제공하지 않는다고 한다?

	Entity 엔티티>> DB 테이블에 대응하는 하나의 클래스
		: @Entity >> 해당 클래스를 엔티티로 선언한다
			: 그러니까 JPA에 의해 해당 클래스가 RDMS 의 테이블과 매핑되어 DB 구조를 만든다
			: 클래스 제한 사항
			*******0. 테이블에 저장할 필드는 final 키워드 사용 불가
				1. 기본생성자가 있어야된다
					: JPA 도 Reflection API 를 사용하기 때문
				2. final, enum, interface, inner 클래스에는 사용 불가
			: 속성
				1. name >> 엔티티 이름을 지정한다
					: 그냥 name 속성을 명시하지 않고 사용 가능하다
		: @Table >> entity 를 db 상에서 어떠한 테이블로 생성할건지(맵핑할건지) 정한다
			: 주로 @Entity 와 함께 쓰이고, 생략 시 엔티티 이름이 테이블명이 된다
			: 속성 
				1. name : 매핑할 테이블 이름 
				2. catalog :  catalog 기능이 있는 데이터베이스에서 catalog 매핑
					: catalog >> 색인. 즉, 데이터베이스의 메타데이터를 저장하는 객체
				3. schema : schema기능이 있는 데이터베이스에서 schema를 매핑한다
					: schema >>도식. 즉, db의 전반적인 명세를 기술한 것.
				4. uniqueConstraints : DDL 생성 시, 유니크 제약조건을 만든다.
