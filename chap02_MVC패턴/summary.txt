	1. 서블릿 컨테이너가 서블릿 인스턴스의 init( ) 메서드를 호출해 초기화
		: 최초 요청시 한 번만 진행, 이후에는 생략

	2. service( HttpServletRequest request, HttpServletResponse response )  메서드 호출
		: 요청방식( post , get .. ) 따라 doPost( ) , doGet( ) , .. 으로 위임해 처리
		: HTTPServletRequest >> 서블릿 컨테이너가 생성되며 서블릿의 service( ) 메서드의 매개변수로 보내진다.

	3. 서블릿을 메모리에서 내려야할 시점에 destroy( ) 호출

							@RequestMapping("/URL") 
								: 다양한 방식의 request  모두 수용 가능
								: 메서드 뿐 아니라 클래스 자체에도 붙일 수 있다
								: 옵션
									: 같은 URL 주소로의 request 더라도 옵션에 따라서 다르게 mapping 시킬 수 있다.
									1. value >> "/URL" 할당
										: 옵션명 생략 가능>> 옵션이 value 밖에 없는 경우 
										: 다중요청 처리 가능>> {  "/URL1" ,  "/URL2" ,  "/URL3" , ...   } 과 같이 중괄호로 묶은 꼴로 할당
										: 변수 삽입 가능 >>  "/URL"  내부에 { 변수명 } 삽입
										:  정규식 적용 가능
											1. 중간에 삽입되는 변수에 정규식 적용 >> { 변수명:쌩정규식패턴 }
											2. 경로 자체에 정규식 적용 >> 경로 표현 중간에 * , ** , ? 그 자체를 삽입
												* == 해당 레벨의 임의의 디렉터리  ---> "/ ex / * " ,   "/ ex / * / hehe " 
												** == 해당 레벨 이하의 임의의 디렉터리  ---> "/ ex / ** "
												? == 아무거나 한 '문자'  ---> "/ ex?/ hehe"

											: https://wildeveloperetrain.tistory.com/316


									2. method >> RequestMethod.GET , RequestMethod.POST ,  RequestMethod.PUT ,  RequestMethod.PATCH,  RequestMethod.DELETE 중 하나 할당
										
									3. params >> {param1 , param2 .. } 할당
 										: 해당 이름의 parameter 가 전달되어야 mapping 시켜줌

									4. consumes >> MediaType.APPLICATION_JSON_VALUE , MediaType.TEXT_PLAIN_VALUE
										: request header 가 특정 content-type 값을 가져야 mapping 시켜줌
										: MideaType.APPLICATION_JSON_VALUE == application/json
										: MideaType.TEXT_PLAIN_VALUE == text/plan

								: @ReuqestMapping( value= "/URL", method= RequestMethod.GET ) 과 동일

							@PostMapping("/URL") : post 방식으로만 수용
								: post  방식의 request 만 수용
								: !! (클래스 자체에는 못 붙이고) 메서드에만 붙일 수 있다
								: @ReuqestMapping( value= "/URL", method= RequestMethod.POST ) 와 동일

						(3) 파라미터 설정
							: 유명한 파라미터 객체
								1. HttpServletRequest request 
								: 클라이언트의 request 사항을 담은 객체
								: 데이터를 클라이언트로부터 받고, 이를 다른 계층으로 전달하기 위해 사용
								: 이것보다는 Model 혹은 커맨드객체를 주로 사용한다 << 귀찮으니까.
								: 메서드
									1. String getParameter("파라미터명") : 특정 파라미터에 대응하는 값을 얻어낸다
										: Parameter vs Attribute
											: parameter >> 폼 등으로 사용자에게 직접 입력받은 내용을 일시적으로 저장한 변수. request 받은 직후에만 값을 사용 가능하고, 한 번 페이지 이동하면 그 값이 사라진다.
											: attribute >> 개발자가 직접 값을 할당한 변수 느낌. 페이지를 이동해도 request 객체가 유지된다면 attribute 값도 유지된다.
										: 반환 값은 항상 String 임을 주의

									2. setAttribute("속성명" , "값" ) : 특정 속성 set
									3. Object getAttribute("속성명"): 특정 속성값 get 
										: 페이지를 여러번 이동하더라도 request 객체가 동일하면 해당 속성을 이용가능
										: 반환값이 Object 이기 떄문에 다양한 값을 뽑아낼 수 있다.

									  
								2. Model model
								: key 와 value 로 이루어진 HashMap
								: 뷰에 데이터를 전달하기 위해 사용
								: Model 객체 vs HttpServletRequest 객체
									: 뷰 템플릿에 정보를 넘겨주기 위해 사용


									: request.setAttribute( "속성명" ,값)  ≒ model.addAttribute( "속성명" ,값)

										: 해당 이름의 속성이 없을 시 해당 이름의 속성을 새로 만들어준다.



							: 파라미터를 대상으로 하는 유명한 어노테이션 
								@Qualifier
									: 해당 메서드에 @Autowired 적용했는데 (해당 타입의 빈이 여러개라 )식별자 구분이 필요한 경우 써준다
									: 속성 >> name .
										: @Qualifier(name ="빈이름") 뿐 아니라 @Qualifier( "빈이름") 으로도 사용 가능하다

								@RequestParam
									: 단순 값( DTO 같은 복합적인 객체가 아니라 int , String 같은 값 ) 같은거 받을 때 자주 사용한다
									: 아무리 기본 int, boolean 등의 값을 저장할 용도더라도, 모종의 이유로 값이 전달되지 않을 경우( required =false 의 상황에서 ) null 을 저장할 수 있어야되기 떄문에 Wrapper 클래스를 써야된다

									: 원리 >> HttpServletRequest 객체를 쉽게 이용하는 것.
										접근제한자 반환값 메서드명( HTTPServletRequest request , ... ){
											String name = request.getParameter("파라미터명");
											int age = Integer.parseInt(request.getParameter("파라미터명2"));
												. . .
										}

										를

										접근제한자 반환값 메서드명( @RequestParam String name, @RequestParam Integer age   ){
												. . .
										}

										와 같이 간소화 하여 쓸 수 있게 해주는거다

									: 개 좋은건 String 타입으로만 DI 해주는게 아니라 다양한 타입으로 알아서 잘 넣어준다.
										:  정확히 말하자면 request 객체가 받은 파라미터 값을 @RequestParam 붙은 대상 파라미터의 타입으로 형변환해준다.
											: 대상 파라미터로 타입변경이 불가능할 경우( ex : 숫자가 아닌 문자열을 숫자로 변환 ) 에러 발생된다

									: 잊지 말아야할 것은 얘는 값을 파라미터 변수에 저장하는데까지만 도와준다는거다. 페이지 이동한 뒤에도 해당 데이터를 사용하고 싶으면 별도로 setAttribute( ) 같은거 해야된다.

										1. name : 값뽑을 파라미터를 "파라미터명"으로 특정한다
											: 속성을 name 만 사용한다면 name 속성명을 생략할 수 있따

										2. required : 파리미터의 필수 여부를 결정한다
											: 할당 가능한 값
												(1) true : 해당 파라미터가 넘어오지 않으면 걍 에러를 발생시킨다<< default
											*******(2) false : 해당 파라미터가 넘어오지 않으면 에러를 발생시키진 않고, 해당 파라미터에 null 값을 대신 할당한다
 													주의)  “/주소?username=” 와 같이 파라미터의 이름만 있고 값이 없으면 값을 ""(빈 문자열) 로 하는 파라미터가 넘어온거다.  아예 파라미터명 자체가 명시되지 않고 request 되어야 파라미터가 없는거다

										3.  defaultValue : 파라미터가 없는 경우 할당할 기본값을 설정

 											주의) 똑똑하게도 빈 문자열이 들어와도 defaultValue 를 적용해준다

								@ModelAttribute
									: DTO 같은 복합적인 객체( int , Integer , String 같은 단순 값 저장용도가 아니라 ) 같은거 받을 때 자주 사용한다
									: 클라이언트측에서넘어온파라미터들과 메서드의파라미터객체의 필드를 바인딩 시켜주는 것

									: 원리 >> 스프링부트가 메서드의 대상 파라미터 객체를 생성시킨 후 그 객체의 setter 계열 메서드를 사용하여 알아서 바인딩 시켜준다
									: 클라이언트측에서 적용대상파라미터타입이 가지는 모든 필드에 대응하여 파라미터들이 넘어와야되는건 아니다. 넘어온것만 채우고 없는건 null 값 같은 거 넣어서 초기화시킨다
									: 주의
										1. 적용대상객체의 필드명과 클라이언트측에서들어오는파라미터명이 완전 같아야된다
										2. 적용대상객체는 자동바인딩시키고자하는 필드에 대응하는 setter 메서드가 있어야된다

											: (그 메서드 내부에서)대상 파라미터에서 직접 꺼내 쓸수도 있고, model.getAttribute 로 꺼내쓸 수도 있다

						1. 변수 사용. 객체 필드 접근 
							1. 기본적으로는  {{ 변수명 }}
								: 변수값이 문자열인 경우 HTML 이스케이프 된다. 그러니까 "<b>호호호</b>" 는 &lt;b&gt;호호호 &lt;/b&gt; 로 인식된다.

							2. HTML 로써 인식 {{{ 변수명 }}}
								: 변수값이 문자열인 경우 HTML 문장으로 인식한다.  그러니까  "<b>호호호</b>" 는  <b>호호호</b> 로 인식된다.
 
 						2. 주석 >> {{! 주석내용 }}

						3. 반복문 과 조건문 >> {{#변수명 }} 실행내용 {{/변수명 }}
							: 변수가 배열이 아니면 조건문으로 사용된다.
								: 변수가 0, false, 빈 문자열이면 거짓간주
								: 변수가 객체면 
									: 섹션변수( {{#변수명}} 의 변수)의 속성은 속성명 자체를 변수처럼 사용해야됨
									: 섹션변수와  같은 레벨에 있는 객체의 속성은 그객체명.속성명 꼴의 변수로 사용해야됨
									ex) 
									{{#객체명 }} 
										<p>{{ 섹션객체의속성명 }}</p>
										<p>{{ 섹션객체와같은레벨의다른객체.속성명 }}</p>
									{{/객체명 }}

								: {{# }} 대신 {{^ }} 을 사용하면 if(! ) 와 같이 동작한다

							: 변수가 배열이면 반복문으로 사용된다.
								: foreach 처럼 첫 요소부터 끝 요솎까지 접근한다
									ex) 
									{{#배열명 }} 
										<p>{{ 요소속성명 }}</p>
									{{/배열명 }}


						5. 다른 mustache 파일 include >> {{> 파일경로 }}
							: 실행시 내부적으로 <html> , <body> , <head> 같은 각 파일의 기본적인 부분은 빠지고 예쁘게 핵심 내용만 include 된다.
